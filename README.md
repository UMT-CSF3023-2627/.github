# CSF3023 System Thinking and Logic: Group Project (K4)

**Universiti Malaysia Terengganu · Faculty of Computer Science and Mathematics · Semester 1, 2026/2027**

This organization hosts the group project repositories for CSF3023 System Thinking and Logic, class K4. Each group analyses one online system, writes five functional requirements, and expresses each one as a flowchart and a pseudocode set. All planning, documentation and discussion happen here on GitHub, and that activity is assessed.

Group repositories are **private**: only the group's members and the lecturer can see them.

---

## Assessment

| Component | Weight | Assessed from |
| --- | --- | --- |
| Written Report (CLO2) | 20% | Final PDF in the group's `/report` folder |

Observation looks at five things: collaboration activity, discussion and communication, contribution transparency, Wiki documentation, and repository organization. If it did not happen on GitHub, it cannot be marked.

## Getting started

1. **Every member:** create a GitHub account with a username close to your real name, and set your full name in your profile.
2. **Every member:** enter your GitHub username in the registration sheet, then accept the invitation to this organization (check your email).
3. **Group:** choose your system in the registration sheet and agree on one repository owner.
4. **Repository owner:** create a **private** repository inside this organization (Owner: `UMT-CSF3023-2627`), not under your personal account. Name it `CSF3023-G<group no>-<system>`, for example `CSF3023-G07-FoodOrdering`.
5. **Repository owner:** under **Settings > Collaborators and teams**, give your group's team **Write** access. The lecturer already has access.
6. **Repository owner:** under **Settings > General > Features**, turn on **Wikis** and **Discussions**.
7. Paste your repository link into the registration sheet.

The GitHub Student Developer Pack is optional; the organization already provides the Wiki for private repositories.

## What every group repository needs

**Folders**

```
CSF3023-G07-FoodOrdering/
├── README.md        system overview, project flow, members and roles
├── introduction/    background and purpose of the system
├── requirements/    FR1 to FR5 descriptions
├── flowcharts/      FR1_flowchart.png ... FR5_flowchart.png (+ source files)
├── pseudocode/      FR1_pseudocode.md ... FR5_pseudocode.md
└── report/          final PDF report
```

**Wiki pages:** Home, Project Plan, FR1 to FR5 (one page each), and Meeting Notes. Every member writes and edits pages with their own account.

**Projects board:** create it in this organization, share it with your team, and link it to your repository. Use the columns To Do, In Progress, Review and Done. Every task is an Issue with one assignee and a due date.

**Discussions:** use them for brainstorming, choosing the five requirements and design decisions. End each thread with the final decision.

**Roles:** each group covers introduction, requirements, flowcharts, pseudocode, formatting and compilation. Record roles in the README and on the Wiki Home page.

## Ground rules

- Use your own account. Never share one account between members.
- Commit often, with clear messages that reference the Issue, for example `Add FR2 flowchart, closes #4`.
- Review each other's work in Issue comments before moving a card to Done, and apply the feedback.
- Decisions made on WhatsApp, Telegram or in person must be summarised in Discussions or Meeting Notes, or they cannot be assessed.
- Do not change your repository to public, and do not create repositories outside this organization.
